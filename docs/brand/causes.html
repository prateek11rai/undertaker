Nine causes of undeath

Checked in this order; the first match wins. Anything else is alive, with the reason.

orphaned

No one is listening

Workflow task scheduled, never started, and no poller on its task queue.
Remedy Start a worker that polls the queue, or lay it to rest.
lost-activity

Sent to a worker that never came

Activity scheduled and never started; no poller on the activity's task queue.
Remedy Start a worker for that activity queue, or lay it to rest.
broken-code

Its own code keeps killing it

Workflow task attempt 2 or more; the last failure is a plain error.
Remedy Fix the workflow code, deploy, then reset past the bad task.
changed-code

Its code changed while it slept

The same, but the failure is non-determinism (TMPRL1100).
Remedy Put the old path behind workflow.patched, deploy, reset.
heartbeat

Stopped breathing

Activity attempt over the threshold; the last failure is a heartbeat timeout.
Remedy Make the activity heartbeat in time, or lay it to rest.
retry-loop

Dies and rises, forever

Activity attempt over the threshold, a real failure, no retry maximum in sight.
Remedy Fix the activity or mark the error non-retryable.
undead-child

Waiting on an undead child

A pending child workflow that is itself undead.
Remedy Fix the child first; its certificate is linked.
long-sleep

Asleep for a very long time

An open timer longer than --long-sleep (7 days by default).
Remedy If the duration is a mistake, fix it and reset.
waiting-signal

Waiting for a visitor who never comes

Nothing pending at all; the last event is older than --quiet.
Remedy Send the signal it handles (names from the worker), or lay it to rest.

Thresholds are flags: --quiet 10m, --attempts 5, --poller-window 2m, --long-sleep 7d. Every remedy comes with the exact temporal command.
