How a certificate is checked

Gemma writes the words. Plain code decides whether they reach the page.

What the model gets

  • the cause and its rule text
  • workflow id, type, task queue, born
  • the evidence list (keyed facts)
  • top stack frames
  • with --source: the enclosing function, only from files inside that folder
  • failure text inside <data> tags, as data
→

What it answers

Ollama JSON schema, temperature 0.2:

{"headline":  "≤ 12 words",
 "diagnosis": "≤ 70 words",
 "evidence":  ["e5", "failure"],
 "next_step": "≤ 30 words",
 "epitaph":   "≤ 14 words"}
→

Checks, in code

  1. Every cited evidence key exists.
  2. Every number is in the evidence.
  3. Every `code span`, file, file:line, activity or signal name is in the evidence or the excerpt.
  4. No other cause is named.
  5. No commands or URLs. (The model never writes commands.)
  6. Lengths hold.
  7. The epitaph has no digits and no identifiers.

All pass

Shown as "written by gemma4:e4b, every fact checked". Cached per workflow state.

Any fail

One retry, with the exact reasons sent back to the model.

Fails again

The template certificate for that cause, built from the evidence and labelled as a template.
